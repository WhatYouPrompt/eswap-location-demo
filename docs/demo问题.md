### 1. 功能范围 (Demo 阶段)

对于 Demo 而言，核心是**“展示业务价值”**（让老板和团队看到地图选址的直观威力），而不是“实现完美的系统闭环”。

| 模块 | 建议 | 是否需要？(Demo) | 落地说明 |
| --- | --- | --- | --- |
| 热力图可视化 | 核心展示功能 | **✅ 必须包含** | **最高优。** Demo 的核心亮点，直观展示需求真空区。 |
| 点位录入表单 | 核心交互功能 | **✅ 必须包含** | 需包含核心字段：坐标、租金/月、电费预估、电网稳定性。 |
| ROI 测算 | 核心辅助功能 | **✅ 必须包含** | **结合表单联动。** 输入成本后，利用 12,000/13,000 PKR 的单双电收入模型，直接在前端算出预计回本周期。 |
| 智能评分展示 | 降级展示功能 | **⚠️ 简化包含** | 不做复杂的 AI 算法，直接写一套静态规则（如：租金低+热力高=90分）。 |
| 审批流程 | 完整业务闭环 | **❌ 暂不需要** | 砍掉。Demo 阶段表单点个“提交”弹个成功提示即可，无需做多角色的流转状态机。 |

### 2. 数据来源

**推荐：方案B（本地 JSON 数据 / 前端 Mock 结合）**

* **原因：** Demo 阶段搭后端 API 太拖慢进度。直接在项目中存放几份针对拉合尔或卡拉奇等目标城市的本地 JSON 文件。
* **做法：** * 伪造一份包含几百个坐标点的 `heatmap_data.json` 用于渲染热力层。
* 伪造一份包含现有电柜坐标的 `existing_cabinets.json`。
* 前端代码通过异步加载这些 JSON，完全能模拟出真实的 API 请求延迟感，未来切成真实后端成本极低。

### 3. Google Maps API Key

使用开源地图框架（强烈推荐，0 成本，免 Key）
方案：Leaflet.js + OpenStreetMap (OSM) 底图

优势： 完全免费开源，不需要任何 API Key，不需要绑定信用卡。只需在前端代码里引入一个 JS 库，直接就能渲染出巴基斯坦（拉合尔、卡拉奇等）的街道地图。

效果： 它支持无缝添加标记点（现有电柜）、画覆盖半径（圆圈）、甚至通过插件（如 leaflet.heat）实现你最需要的热力图可视化。

Demo 契合度： 完美。对于读取本地 JSON 假数据并在前端渲染的 Demo 来说，Leaflet 是全球开发者的首选“平替”。

### 4. 部署方式

**推荐：部署到 Vercel 在线演示**

* **原因：** 本地运行演示的沟通成本太高（需要投屏或截视频）。将前端代码推送到 GitHub 并关联 Vercel 自动构建，几分钟就能拿到一个 `xxx.vercel.app` 的公网链接。把链接发给高管或城市经理，他们用自己的电脑点开体验，说服力极强。
* **注意：** 如果使用 React/Vue 等单页路由，记得在根目录配置 `vercel.json` 做好路由重写（Rewrites），避免刷新页面出现 404 错误。

### 5. 页面数量

**推荐：单页面集成（地图主导的仪表盘布局）**

* **原因：** 选址是一个高度依赖地理空间属性的操作，跳出地图去填表单会打断思路。
* **布局方案：**
* **主视觉：** 占据屏幕 70%-100% 的全屏 Google Map，展示热力图和现有站点。
* **交互区：** 采用**右侧抽屉（Drawer）**或**悬浮面板（Floating Panel）**。当用户在地图上点击某个点时，右侧划出“录入表单”；填完表单后，面板直接切换显示“评分与 ROI 测算结果”。
* 这样可以做到操作不离地图，体验最流畅。


1. ROI 测算参数 (Demo 预设值)
在 Demo 阶段，你可以将以下数值作为代码里的全局常量（Constants），方便后续真实数据接入时随时替换：

柜机投入成本 (CAPEX)： 设定为 600,000 PKR（约合 $2,100 USD，包含一台标准 8-12 仓智能柜体及海运/关税的模拟均摊成本）。

单/双电用户比例： 设定为 30% 单电用户（12,000 PKR） / 70% 双电用户（13,000 PKR）。因为目标群体多为跑单骑手，对续航要求高，双电通常是主力。因此，每个活跃用户的混合 ARPU（每用户平均收入）可以按 (12000*0.3) + (13000*0.7) = 12,700 PKR/月 来进行简易测算。

月均运营成本范围 (OPEX)： 设定为 35,000 - 55,000 PKR/月。这个区间包含：

场地租金：10,000 - 20,000 PKR

电费损耗：20,000 - 30,000 PKR

网费及折旧摊销：约 5,000 PKR

2. 评分规则细化
你提出的权重分配非常合理，完美契合了“找需求”和“控成本”的业务痛点。

打分模型：

骑手活跃度 (30%)：热力图覆盖度

POI 密度 (25%)：周边 1km 内外卖站点/商圈数量

租金成本 (20%)：低于预期为高分，高于预期扣分

电网稳定性 (15%)：停电频率评估

竞品距离 (10%)：与竞品柜机的缓冲距离

Demo 实现方式： 绝对可以直接用 Mock 数据模拟。
在前端表单中，只要 BD 输入了“租金”和“电网稳定性（如下拉菜单选 High/Medium/Low）”，其余三个地理相关参数（骑手活跃度、POI、竞品）你可以直接在代码里写一个 Math.random() 生成 60-100 的随机分数，最后加权相加得出一个总分。这样既有了交互感，又省去了立刻对接复杂地图算法的时间。

3. 现有电柜数据
Demo 数量： 建议在地图上只展示 15 - 30 个点位。

原因： 数量太少（个位数）体现不出“系统”的价值，老板会觉得看 Excel 就行；数量太多（几百个）如果在纯前端渲染，容易让浏览器卡顿，且视觉上密密麻麻，失去了寻找“盲区”的焦点感。20 个左右的站点配合周边几片红色的热力区，视觉冲击力最强。

4. 目标城市
强烈建议：单城市首发，聚焦“拉合尔 (Lahore)”。

原因： 相比卡拉奇的复杂路况和极度分散的片区，拉合尔（例如 Gulberg 或 Johar Town 区域）的商业区和骑手活动轨迹相对更集中，电网条件也更有代表性。Demo 阶段做多城市切换纯粹是增加前端工作量，把拉合尔的一个区讲透，就足以证明这个选址工具的 MVP 价值了。
