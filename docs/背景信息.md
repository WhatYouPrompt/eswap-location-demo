1. 业务背景 (Business Background)
目前的规模（城市数量、柜机数量）：
目前 ESwap 处于快速扩张期，主要覆盖巴基斯坦的核心城市（如拉合尔、卡拉奇、伊斯兰堡等）。换电柜数量正在从早期的几十台向百台甚至更大规模突破，单电（12,000 PKR）和双电（13,000 PKR）用户的稳步增长对站点的密度和合理性提出了更高要求。(注：具体数字你可在定稿时填入真实数据)。

当前选址方式的痛点：

严重依赖人工经验： BD（商务拓展）团队主要靠“扫街”和直觉找点位，缺乏数据支撑，试错成本极高。

供需不匹配： 现有点位可能偏离了真正高频跑单骑手的核心活动热区，导致部分柜机利用率低，而热点区域又面临电池断供。

基础设施盲区： 巴基斯坦当地的电网稳定性（停电频率）和物业改造成本在前期勘察中经常被遗漏，导致签了约却无法顺利通电运营。

2. 目标用户 (Target Users)
谁来做选址决策：

一线 BD： 负责使用系统在移动端或 Web 端录入潜在点位信息、照片和租金报价。

城市经理 / 运营负责人： 负责依据系统给出的评估分数和回本周期预测，进行复核与审批。

现在的选址流程：
BD 线下踩点 -> 手工记录周边业态（如外卖站点、商圈） -> 询问场地租金和电力情况 -> 汇总到 Excel 提交给城市经理 -> 城市经理线下复勘或凭经验拍板 -> 签约推进。整个链路数据断层，且无法沉淀选址模型。

3. 期望功能 (Expected Features)
智能选址系统需要的数据输入：

内部业务数据： ESwap App 沉淀的骑手历史轨迹数据、高频换电时间段、现有柜机的吞吐量。

外部地理数据： 强依赖 Google Maps API 获取的 POI 数据（如餐厅密集区、物流集散中心、核心商圈）。

成本与基建数据： 目标点位的预期租金、场地费、巴基斯坦各区域的电网稳定性评级。

期望的输出：

可视化选址热力图： 叠加骑手活跃度与现有电柜覆盖半径，直观暴露“需求真空区”。

智能评分与推荐列表： 对 BD 录入的意向点位进行多维度打分（满分 100），并预测该点位的日均换电单量。

投资回报（ROI）测算： 自动输出该柜机的预计回本周期，辅助毛利指标的达成。

4. 约束条件 (Constraints)
技术栈偏好：
前端可考虑使用 Vercel 进行轻量级快速部署。后端数据处理和爬虫/API 接入（特别是 Google Maps API 的多 Key 管理与调用）使用 Python 进行处理。整体代码可通过 GitHub 管理，并利用 Trae 等 AI 工具辅助快速生成业务逻辑代码。

预计上线时间：
大约 4-6 周内完成核心功能的上线跑通。

MVP 还是完整版本：
绝对的 MVP 版本。第一阶段不追求极其复杂的 AI 预测算法，而是优先实现”内部数据+地图 API 的数据可视化映射”和”标准化的线上审批流”，把线下的 Excel 搬到线上，用热力图指导 BD 去哪里找点，先让流程跑通。
